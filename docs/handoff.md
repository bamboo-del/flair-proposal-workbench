# 线上版本交接

| 位置 | 责任 |
| --- | --- |
| index.html、assets/portal.js、assets/portal.css | 登录、项目列表、假设书、计价、版本、团队与证据 |
| assets/app.js、proposal.cjs | 同一组测算逻辑、服务器项目输入校验、已保存版本的客户视图 |
| server.cjs、store.cjs | 身份认证、角色校验、项目修订、镜像快照、版本分享、附件存储 |
| scripts/verify-workbench.cjs | 162 个组合与预算下降、过期档期、面积补录、覆盖去重、导出的回归 |
| scripts/verify-online.cjs | 服务端应用处理函数、两项目独立、并发版本检查、权限、固定分享、撤回和重启持久化 |
| Dockerfile、compose.yaml | 容器构建与单实例持久化 |

## 上线前验证

1. 用两个授权且脱敏的真实业务导出案例验证字段映射、来源与时点。调研资料仅接入获准的来源。
2. 验证不同场景缺资源、刊例或面积的表现。业务项目刊例由团队录入并明确是已审批的区间口径。具名单点专价、签单和销售锁位需要单独确认流程。
3. 当前地理界面仍是线网示意；目标圈覆盖率按已导入命中计算，未验证覆盖按工作台估算展示。地图 API、真实几何、人流与曝光估算的口径需要实数验收。
4. 执行配置按夜间容量与停工日期分批，登记缓冲、异常预案和监测附件。使用业务数据复核具体施工窗口、备选点位与上下刊责任。
5. AI 可从团队成员确认脱敏的 Brief 生成初稿，服务器配置模型后验收。确认取数、假设与输出都能追溯到证据，不将估算包装成实际效果。
6. 从最终提交构建容器，完成浏览器操作、TLS、最小权限、数据卷、重启和备份恢复验证。项目组验收后再发布。
