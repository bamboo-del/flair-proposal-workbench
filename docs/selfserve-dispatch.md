# 客户自助提案 · 执行调度与变更单

本文件说明 `feature/client-selfserve-dispatch` 分支新增的三块能力、运行方式、现场演示路径和验收结果。

## 新增内容

| 位置 | 作用 |
| --- | --- |
| `client.html`、`assets/client.js` | 客户自助入口 `/client`：一段话预填 → 七要素表单 → 实时检查与冲突 → 生成草稿 → 预览、导出、分享、提交审核、基于此版修改 |
| `ops.html`、`assets/ops.js` | 团队执行调度页 `/ops`：客户授权与草稿审核、执行配置、车级台账、初始计划、变更单预览与应用 |
| `assets/client.css` | 两个页面与导出提案共用样式 |
| `lib/ledger.cjs` | 客户入口用的线路级库存：沿用 `assets/data.js` 的合成线路与点位，加确定性的合成占用记录和地铁面积 |
| `lib/selfserve.cjs` | 表单校验、规则选点（硬条件过滤 → 覆盖优先 → 按目标分配预算 → 回填）、必选资源冲突与替代、覆盖证据、费用、施工批次、监测交付、七要素逐条回应、版本差异 |
| `lib/dispatch.cjs` | 车级排车（硬约束过滤 → 排序 → 按夜次与单夜容量分配）、变更单统一入口、重算、差异、任务先后与责任方、通知模板、缺口与可调整条件 |
| `lib/ai.cjs` | 可选 DeepSeek：口语需求预填、方案摘要与取舍、变更通知；结构校验 + 数字溯源校验，失败回退规则或模板 |
| `lib/render.cjs` | 草稿 HTML：页面预览、`/d/:token` 只读分享和 HTML 导出共用；另有 CSV 资源清单 |
| `lib/routes.cjs` | `/api/client/*`（仅客户角色）与 `/api/projects/:id/{client-drafts,clients,dispatch,changes}`（团队） |
| `scripts/verify-selfserve.cjs` | 规则、调度、AI 回退、完整 HTTP 流程与权限、重启恢复 |
| `scripts/seed-demo.cjs` | 本地演示数据：样例项目、`demo.client`、`demo.editor`、12 台合成车计划 |

## 运行

```bash
cp .env.example .env        # 填 ADMIN_PASSWORD（12 位以上）；可填 DEMO_CLIENT_PASSWORD / DEMO_EDITOR_PASSWORD
npm test
npm run demo:seed           # 未填演示密码时随机生成并打印一次
npm start                   # http://127.0.0.1:3000
```

- 团队工作台：`/`；执行调度与客户草稿：`/ops`；客户入口：`/client`。客户账号登录 `/` 会被引到 `/client`。
- 开通客户：管理员在工作台「团队成员」以「客户」角色建账号，再到 `/ops` 当前项目「授权访问本项目」。`POST /api/team` 也可直接带 `projects`。
- AI：服务器环境变量 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`，可选 `AI_TIMEOUT_MS`（默认 15000）。Key 只在服务端读取，不下发浏览器。

## 权限与数据边界

- `client` 角色只能调用 `/api/session` 和 `/api/client/*`；团队接口一律 403。团队账号调用客户接口也是 403。
- 客户只看到 `client_access` 授权的未归档项目，只读写自己生成的草稿；访问其他项目或其他客户的草稿返回 404。
- 草稿生成后不可修改。「基于此版修改」会生成新草稿并记录上一版与差异；分享链接固定指向当时那一版。
- 客户草稿不是正式报价：正式报价、锁位、执行确认沿用团队的固定版本与审核流程。团队在 `/ops` 采纳或退回，结论回显给客户。
- 变更单只生成预览；团队点击「确认并应用」才更新执行计划，且基于的计划版本必须未变（否则 409）。有缺口的预览不能应用（422）。通知始终是草稿，系统不发送。

## 现场演示路径

1. **客户自助**：`demo.client` 登录 `/client` → 在「用一段话描述需求」粘贴口语需求，勾选已脱敏，点「提取到表单」→ 逐项确认七要素 → 右侧实时检查显示数量、费用区间、覆盖 → 「生成方案」。
2. **改条件**：点「分享只读链接」固定第 1 版 → 「基于此版修改」→ 预算 200 改 100、开始日改 2027-06-05 → 生成第 2 版，页首「本次修改的影响」列出保留、数量调整、替换、移除（附原因）、新增，以及覆盖、费用、档期、施工夜变化。打开分享链接仍是第 1 版。
3. **硬约束冲突**：资源清单勾选 `S911 路` 2 辆（六月被合成占用）→ 实时检查给出原因与选项：改档期到 2027-07-01、改用同商圈线路、移除。客户点选后冲突消失，再生成。导出 HTML／CSV／JSON，提交团队审核。
4. **执行调度**：`demo.editor` 登录 `/ops` → 看到客户草稿并可采纳／退回 → 执行配置默认 `S9DEMO`、12 台合成车、起投 10、每晚 5、上刊前 3 晚、误 1 补 2 → 初始计划 10 台排在 05-07、05-08 两晚，1 台备用。
5. **临时进保**：变更单选「已排车辆临时进保」、`SYN-03`、05-08 至 05-20 → 预览显示替补 `SYN-08`、05-09 晚施工、受影响的制作单、T1–T6 任务（责任方与前置）、客户通知草稿 → 可编辑通知 → 「团队确认并应用」。
6. **缺口**：变更单选「雨天占用施工窗口」，停工夜 05-08、05-09 → 「施工夜次缺 1 晚，只能排 5／10 台」，列出提前开工、提高单夜容量、推迟上刊，应用按钮禁用。再连续让 `SYN-01`、`SYN-02` 进保 → 「可用车辆缺 1 台，只能排 9／10 台」。

## 验收结果（2026-11-21，本地 Windows，Node 24.21，AI 未配置）

| 项 | 结果 |
| --- | --- |
| `npm test` | 6／6 通过：原有工作台回归（162 组合）与在线流程，加 5 组新测试 |
| 浏览器端到端（应用内浏览器） | 按上面 1–6 步操作通过：口语预填、实时检查、生成第 1–3 版、差异、冲突选项回填、分享固定版本、导出、提交审核、团队查看与审核、初始计划、进保替补并应用、雨天缺口与缺车缺口不可应用 |
| 刷新恢复 | 刷新 `/client` 后恢复项目、未提交的表单（含必选资源）和最近草稿；服务重启后会话、草稿、调度计划、分享链接仍在 |
| 跨项目权限 | 客户访问团队接口 403、访问未授权项目 404、读取他人草稿 404；团队调用客户接口 403；草稿按项目隔离（自动化测试覆盖） |
| AI 关闭 | 预填走关键词规则，摘要与通知走模板，主流程全部可完成。AI 成功、编造数字、虚构车辆、超时四种情况用模拟响应测试 |

验收中发现并已修复：`history` 函数名遮蔽浏览器 `window.history` 导致页面停在「正在计算」；贪心选点可能漏掉目标商圈（加了覆盖优先一轮）；冲突替代里出现可售 0 的线路；冲突时未覆盖告警刷屏；已上车车辆进保时任务标题与说明不一致。
