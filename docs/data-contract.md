# 数据契约

本仓库使用合成样例。业务项目的授权数据由具备权限的成员从红豆与大数据平台导出，导入私有工作区。原始企业资料、账号、合同、真实客户信息和成交价不进入公开 Git 仓库。

| 输入 | 当前方式 | 关键校验 |
| --- | --- | --- |
| 红豆公交／地铁库存 | CSV、TSV、XLSX | 线路／点位和媒体形式、等级、可售数量、查询起止日期与时点；方案日期完全匹配且空位为正才参与报价。 |
| 大数据平台覆盖 | 按模板整理的 CSV、TSV、XLSX | 按媒体名称、公交形式和目标圈关联库存，同圈重复命中去重。|
| 项目刊例 | 计价配置页 | 每辆／处对应的 30 天发布区间、仅作用于发布费的折扣、公交制作区间、地铁每平方米制作费、来源或版本。|
| 执行证据 | PNG、JPEG、PDF、文本 | 每件 2 MB 以内，保存阶段、说明、提交人和时间；团队登录后可查看。|

库存缺查询区间可人工填当次实际区间。空位为零不会入选。缺面积只计算已知费用。已导入只表明有镜像依据，实际资源及特殊合同仍需业务复核。

每次保存后的不同镜像形成独立批次，可恢复为项目草稿。报价版本冻结配置、库存和客户可见的证据摘要，后续导入不会修改已发布的版本。

客户自助入口目前使用 `lib/ledger.cjs` 的合成线路级库存与合成占用记录，只支撑线路推荐和初步估价；车级排车需要车级台账（车号、车型、画面形式、状态、回场时间、占用区间），未接入时只能用明确标记为 `SYN-*` 的合成车辆演示。合同起投量、缓冲与「误一补二」按项目配置并记录规则来源。

预期后续采用有明确授权的只读接口补充同步。当前可完整走镜像导出、归档、版本关联和业务复核链路。
